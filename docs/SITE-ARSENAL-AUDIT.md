## 4. How it works

```
src/lib/site-schema.ts   SiteData (zod): the only contract between content and templates
src/lib/templates.ts     TemplateDef: tokens, fonts, default section list, fingerprint
src/templates/<id>.ts    one template = tokens + Google Fonts URL + section list (no page code)
src/sections/            shared kit: hero, services, about, gallery, custom, visit, faq, close
src/sites/<slug>.json    one content file per site
src/sites/index.ts       GENERATED by scripts/index-sites.mjs (static imports of every JSON)
src/app/[slug]/page.tsx  renders one site; generateStaticParams lists every slug
src/app/page.tsx         internal gallery: every template and every mockup, with links
src/app/robots.ts        Disallow: / for the whole host
scripts/new-site.mjs     writes a stub site JSON
scripts/shoot.mjs        Playwright screenshots at 1440 and 390 px + console-error and overflow checks
```

Section variants: hero (split, poster, centered, banner, stacked), services (rows, grid, columns, menu, tiles), about (quote, split), gallery (mosaic, strip), custom (strip, note, steps), visit (split, card), faq (list, columns), close (band, card, statement). A section with no data hides itself and drops out of the nav.

Per-lead tailoring is data only: `design.accent`, `design.fonts`, `design.sections` and one `custom` section. The repo's rules forbid editing template code for a single lead.

## 6. Gaps against the KRIV Previews plan

Checked against plan section 3 (guardrails) and section 4 (schema). Items 1 to 3 matter most.

| 2 | **The home page lists every site.** `/` is the internal gallery with the name, template and city of every mockup and links to them. Deployed publicly, one lead could browse all the others. The 404 page links back to it. | `src/app/page.tsx`, `src/app/not-found.tsx` | Guardrail 6 |

## 9. Recommendation for Phase 1

The plan says to port 1 to 3 templates into a new `kriv-previews` app. Site Arsenal is already that app in all but data loading and guardrails, so porting a few templates would throw away working parts. Recommended instead, subject to Kriv's choice:

1. Create `Krivative/kriv-previews` from Site Arsenal's code (copy, not a fork link), keeping all 20 templates and the section kit. Keep Site Arsenal as the design workshop where templates are built and reviewed.
2. In `kriv-previews`:
   - `basePath: "/for"`.
   - Replace the generated static index with `getLead(slug)` behind an interface; MVP JSON adapter, later database adapter. Render on request and cache per slug, so a new lead needs no deploy.
   - Remove the public gallery; `/for` and unknown slugs return a real 404 with no links to other leads.
   - Add `sources` (required, non-empty), `createdAt`, `expiresAt` (default +30 days), `status`; add the expired page.
   - Replace the ribbon with the exact guardrail 2 banner.
   - Add the `X-Robots-Tag: noindex, nofollow` header for every response.
   - Make address and phone country-neutral; `lang` per lead.
   - Decide on live CTAs (finding 9).
   - Add `typecheck` (`next typegen && tsc --noEmit`) and `test` scripts and tests for the guardrails; add `playwright` to `devDependencies`.
   - Use npm (as Site Arsenal does) or switch to pnpm; the plan's acceptance commands should match.
